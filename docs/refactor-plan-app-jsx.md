как код будет двигаться. Поведение приложения менять нельзя: это чистое перемещение и разрезание.

## 2. Принципы

1. **Ноль изменений поведения.** Каждый этап — только перенос; никаких «заодно поправлю».
2. **Один этап — один коммит**, после каждого — полная проверка (раздел 5). Откат — `git revert` одного коммита.
3. **Зависимости идут в одну сторону:** `styles.js`/`constants.js` → компоненты → `App.jsx`. Циклических импортов нет.
4. Публичный экспорт `buildShareUrl` из `App.jsx` сохраняется (его импортирует `src/App.share.test.js`).

## 4. Этапы

**Этап 1 — перенос листовых компонентов и стилей (без изменения логики).**
Порядок (от того, от чего зависят остальные): `styles.js` → `constants.js` → `components/common.jsx` →
`RecipeModal.jsx` → `ProModals.jsx` → `components/account/*` → `ResultView.jsx` → `LastPlanGateView.jsx`.
Для каждого файла: вырезать код как есть, добавить `import`/`export`, импортировать обратно в `App.jsx`.
Общие вспомогательные функции, которыми пользуются и `MealPlanner`, и вынесенные компоненты
(`pluralPeople`, `formatResetDate`, `pluralDaysRu`, …), — в `src/lib/format.js`.

**Этап 2 — хуки вокруг `MealPlanner`.** Вынести группы состояния и эффектов, которые не пересекаются:
`usePlanStatus` (тариф, лимит), `useFamily`, `usePlanSlots`, `useReferral`, `usePriceRetry`
(автоповтор цен), `useWizardProfile`. `MealPlanner` остаётся склейкой. Это самый рискованный этап
(порядок эффектов, замыкания), делать после этапа 1 и по одному хуку за коммит.

**Этап 3 (опционально).** Тесты на компоненты (jsdom + Testing Library) для самых хрупких мест:
окно рецепта (портал), баннер деградации, история планов, пауза семьи.

## 5. Проверка после каждого этапа

1. `npm test` (фронтенд, сейчас 289), `npm run build`.
2. **Статическая проверка неопределённых имён** — самая частая ошибка при переносе (сборка её не ловит, это
   ошибка времени выполнения): ESLint с `no-undef` и `react/jsx-no-undef`, `react/jsx-uses-vars`
   (одноразовым запуском, без добавления в проект).
3. **Проход по экранам в браузере** (ширина 375 px, настоящий локальный бэкенд, `#tgWebAppData=…`, как в
   `docs`/памяти проекта): новичок — все шаги визарда; готовый план; рецепт; замена блюда; Аккаунт с историей, семьёй,
   рефералами; окна Pro и «ещё один план»; экран лимита; деградированный план (имитация отказа каталога); консоль без ошибок.
4. Сравнение размера сборки до/после (сильное расхождение — повод посмотреть).

## 6. Риски и как их закрываем

| Риск | Закрытие |
|---|---|
| Неопределённое имя после переноса (ошибка только на экране) | ESLint `no-undef`/`jsx-no-undef` + проход по экранам |
| Потеря замыкания: компонент использовал переменную из `MealPlanner` | в `App.jsx` компоненты, получающие данные пропсами; перенос только тех, что уже принимают всё пропсами |
| Циклические импорты | зависимости только вниз (раздел 2, п. 3); проверка сборкой |
| Сломанный глобальный стиль / порядок CSS | стили — один модуль, как есть |
| Раздувание сборки | сравнение размера |
| Конфликт с параллельной работой над приложением | этап 1 делается быстро, за один подход, без параллельных правок `App.jsx` |
