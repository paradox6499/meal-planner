## 1. Резюме

Денежная часть стала заметно надёжнее первого раунда:
- журнал `plan_generations` — единственный источник правды для лимита и кредитов;
- проверка лимита и запись по-прежнему идут без `await` между ними;
- вебхук ЮKassa перепроверяется, есть сверка и возвраты;
- удаление аккаунта больше не обнуляет лимит и рефералы;
- миграции версионные, у внешних запросов есть таймауты, фоновые задачи не накладываются.

Новые риски пришли вместе с каталогом и переездом:
- **частичный отказ каталога** (не ответила одна категория рецептов) всё ещё списывает бесплатный план — пользователь получает план без завтраков с объяснением «под ваши аллергии»;
- **прокси каталога** даёт любому пользователю записывать произвольный «спрос» для подогрева: это выключает подогрев и раздувает базу;
- **эксплуатация на VPS** держится на внутренних алертах процесса: внешнего мониторинга нет, бэкап только в Telegram, ранбуки описывают Render;
- **политика конфиденциальности** после переезда говорит неправду о месте хранения данных.

**Звать первых платящих можно** после двух исправлений на час-два каждое: частичный отказ каталога (раздел 3, п. 1) и текст политики (п. 2). Внешний мониторинг (п. 3) желательно поставить в ту же неделю.

## 3. Слабые места (по вероятности × ущербу)

### 1. Частичный отказ каталога списывает бесплатный план [ПОДТВЕРЖДЕНО] — ВЫСОКИЙ

`src/lib/vkusvillRecipes.js:546, 555`: если не ответила одна категория (например, завтраки), её пул становится пустым, а ошибка сохраняется, **только если упали все категории**. Дальше `assessPlanBuild` (`src/lib/planBuild.js:18`) не видит ни `catalogError`, ни `mostlyUnpriced` — сборка засчитывается. Экран при этом пишет «Под ваши аллергии/рацион не нашлось рецептов для: Завтрак» (`src/components/ResultView.jsx:270`).

Сценарий вполне реальный: на холодном кэше наш же общий шлюз отдаёт 429, если слот не освободился за 8 с (`server/src/vkusvillPrices.js:50` и далее, `acquireUpstreamSlot`). То же бывает при частичной блокировке QRATOR. Воспроизведение — приложение A: `pools={"breakfast":0,"main":8}`, `warnings=["Завтрак"]`, `degraded=false`.

Тест `src/lib/vkusvillRecipes.test.js:611` («часть категорий ответила — план возможен») закрепляет это поведение, но денежное последствие не проверяет.

- **Цена исправления — 1–2 часа.** `fetchVkusvillPools` возвращает `failedCategories`. `runFinish` считает сборку вырожденной с причиной «каталог не ответил для: Завтрак», а повтор цен её не «чинит» — нужна пересборка. Плюс тест в `App.flows.test.jsx`.
- **Цена бездействия:** бесплатные планы, потраченные на сбой; ложное объяснение «аллергии»; обращения в поддержку.

### 2. Политика конфиденциальности устарела; полный бэкап за границу [ПО КОДУ] — ВЫСОКИЙ (юридически), вероятность 100 %

**Цена исправления:** текст — 1 час; бэкап в российское хранилище — день (см. стратегический п. 1). **Цена бездействия:** документ, на который соглашаются при оплате, говорит неправду; локализация формально не достигнута.

### 3. Эксплуатация: никто не узнает, что сервер лёг [ПО КОДУ] — ВЫСОКИЙ

- **Мониторинг только изнутри процесса** (`catalogMonitor.js`, дайджест, алерты оплаты). Если упал VPS, Caddy или сертификат — алертов нет: слать их некому.
- **`/health` не трогает базу** (`server/src/app.js:420`): процесс с испорченной или заблокированной БД отвечает `{ok:true}`.
- **`deploy.sh` проверяет только `/health`** и не умеет откатываться (`server/deploy/deploy.sh:6–15`). Откатить код после миграции нельзя: `runMigrations` (`db.js:385`) откажется стартовать на более новой схеме, нужно восстановление базы. Это нигде не записано.
- **ЮKassa повторяет вебхук сутки**, сверка смотрит `pending` не старше 48 ч (`payments.js`, `RECONCILE_MAX_AGE_MS`). Простой дольше двух суток оставит оплаченные платежи без выдачи навсегда.
- **Нет обработчика `SIGTERM`** (`server/src/index.js`): каждый `deploy.sh` обрывает запросы в полёте. Деньгам это не вредит (вебхуки повторятся, учёт сборки на клиенте мягкий), но сборка в момент деплоя может не засчитаться.
- **Бэкап только в Telegram, раз в сутки.** Локальных копий с ротацией на VPS нет. Снимки диска Timeweb — неизвестно (вопрос 2).

**Цена исправления:** внешняя проверка `/health` с `SELECT 1` и версией схемы — 1–2 часа; локальные копии с ротацией — час. **Цена бездействия:** простой на часы или дни без ведома автора, в худшем случае — потерянные оплаты.

### 4. Мусорный «спрос» для подогрева выключает подогрев и раздувает базу [ПОДТВЕРЖДЕНО] — СРЕДНИЙ

`server/src/app.js:942`: для `vkusvill_recipes` спрос записывается в `warm_targets` **до** запроса в каталог, при любом исходе и с любыми аргументами (до 6 000 байт, `server/src/vkusvillProxy.js:49, 66`). Подогрев берёт 20 самых частых запросов **раньше** базовых страниц (`server/src/warmup.js:113`), а при первой же ошибке встаёт на паузу на 30 минут целиком, вместе с ценами (`warmup.js:137`).

Воспроизведение — приложение B:
- 40 одинаковых мусорных запросов получают 502, но становятся первыми в очереди подогрева;
- следующий тик идёт в каталог с этими аргументами, получает ошибку и встаёт на паузу на 30 минут;
- 50 уникальных запросов дают 51 строку на 251 КБ.

При общем лимите 60 запросов в минуту на пользователя это до ~86 тыс. строк и ~500 МБ в сутки с одного аккаунта; срок хранения — 14 дней (`maintenance.js:22`). Ещё и запросы с мусорными аргументами уходят во ВкусВилл с нашего IP — ровно то, за что QRATOR блокирует.

**Цена исправления — 1–2 часа:**
- писать спрос только после успешного ответа;
- проверять аргументы по схеме, которую реально шлёт фронтенд (ключи и типы как в `seedRecipeTargets`);
- держать не больше ~200 строк;
- сбой пользовательской цели не должен ставить паузу — цель просто выбрасывается.

**Цена бездействия:** один недоброжелатель держит подогрев выключенным (больше планов без цен у всех) и заполняет диск, на котором лежат платежи.

### 5. Один аккаунт может занять весь общий лимит каталога [ПО КОДУ] — СРЕДНИЙ

Общий шлюз — 50 запросов в минуту на весь сервер (`server/src/vkusvillPrices.js:50`). Прокси на одного пользователя допускает 120 запросов в минуту и 400 живых в час (`server/src/app.js:71–72`), цены — 200 за запрос и 600 в час (`app.js:63–64`). Отдельного поминутного потолка живых запросов на пользователя нет: один аккаунт (или скрипт) забирает все 50 слотов минуты, и у остальных сборки уходят в 429 после 8 с ожидания, то есть в план без цен (или в п. 1).

**Цена исправления — 1 час:** поминутный потолок живых запросов на пользователя (порядка 15) в `takeBudget`, чтобы общий шлюз нельзя было занять одним человеком. **Цена бездействия:** деградация для всех во время чужой «сборки» скриптом.

### 6. Сообщение владельцу семьи: спам и ссылки от имени бота [ПО КОДУ] — СРЕДНИЙ/НИЗКИЙ

`server/src/app.js:857`: при каждом успешном вступлении владельцу уходит сообщение с `auth.firstName` как есть (`server/src/webhook.js:67–69`). ## Приложение B. «Спрос» для подогрева: пауза и рост базы

Скрипт из `server/` (`node probe.mjs`, Node ≥ 22.5). Каталог заменён заглушкой: на аргументы со словом «мусор» он отвечает ошибкой.

```js
import { createHmac } from "node:crypto";
const S = new URL("./src/", import.meta.url).href;
const realFetch = globalThis.fetch;
globalThis.fetch = async (url, opts) => {
  if (String(url).startsWith("https://mcp.vkusvill.ru")) {
    const bad = JSON.stringify(JSON.parse(opts.body).params.arguments).includes("мусор");
    const inner = bad ? { ok: false, error: { message: "invalid argument" } } : { ok: true, data: { items: [] } };
    return new Response(JSON.stringify({ result: { content: [{ text: JSON.stringify(inner) }] } }), { status: 200 });
  }
  return realFetch(url, opts);
};
const { openDb, listWarmTargets } = await import(S + "db.js");
const { createApp } = await import(S + "app.js");
const { runWarmupTick, getWarmupPausedUntil } = await import(S + "warmup.js");
const TOKEN = "1:T";
const initData = (id) => {
  const f = { user: JSON.stringify({ id, first_name: "T" }), auth_date: String(Math.floor(Date.now() / 1000)) };
  const dcs = Object.entries(f).sort(([a], [b]) => (a < b ? -1 : 1)).map(([k, v]) => `${k}=${v}`).join("\n");
  const sk = createHmac("sha256", "WebAppData").update(TOKEN).digest();
  return new URLSearchParams({ ...f, hash: createHmac("sha256", sk).update(dcs).digest("hex") }).toString();
};

for (let i = 0; i < 40; i++) await call({ q: "мусор", page: 1, id_category_filter: "x" });
```
