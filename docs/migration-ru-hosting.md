# Переезд сервера «Съедим» с Render на российский хостинг

Зачем: `/diag` (04.10.2026, дважды) показал, что с Render ВкусВилл не отвечает — таймаут 8 с, без HTTP-кода.
С домашнего адреса тот же запрос отвечает за ~1 с (проверено `scripts/probe-vkusvill.js`). Похоже на то,
что адреса зарубежных дата-центров блокируются на стороне ВкусВилл (QRATOR). Пока сервер там, цены в
приложении не работают ни у кого. Второй повод — 152-ФЗ: база с telegram-id пользователей должна лежать в РФ.

Цены и сроки ниже — **ориентиры, проверьте на сайтах провайдеров**.

## Шаг 0. Проверить гипотезу за ~100 ₽ и 30 минут (до любого переезда)

Прежде чем переносить всё, убедиться, что с российского адреса ВкусВилл отвечает.

1. Арендовать самый дешёвый VPS в РФ с **почасовой** оплатой (Timeweb Cloud или Selectel; Москва/СПб,
   Ubuntu 24.04, 1 vCPU, 1–2 ГБ). Достаточно на час-два.
2. Зайти по SSH, поставить Node (≥ 22.5; нужен встроенный `node:sqlite`) и склонировать репозиторий:
   ```bash
   curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash - && sudo apt-get install -y nodejs git
   git clone https://github.com/paradox6499/meal-planner.git && cd meal-planner/server && npm ci --omit=dev
   node scripts/probe-vkusvill.js
   ```
3. Результат:
   - «каталог доступен» → переезжаем на этот же хостинг (сервер можно не удалять, а сделать боевым);
   - «не ответило 3 из 3» → этот провайдер/диапазон адресов не подходит: попробуйте другого провайдера
     (шаг 0 повторяется за те же копейки). Если не проходит ни с одного российского адреса — значит, дело не в
     адресе; тогда нужен контакт с ВкусВилл (см. «Если не поможет»).

## Шаг 1. Выбор и покупка

- **Провайдер.** Timeweb Cloud, Selectel, Yandex Cloud, Beget — любой с серверами в РФ. Что проверить у
  выбранного: дата-центр в РФ указан в договоре (нужно для 152-ФЗ), оплата с расчётного счёта ИП или картой,
  закрывающие документы. Мой выбор по простоте — Timeweb Cloud; Selectel — если захотите S3-хранилище для бэкапов
  рядом.
- **Тариф.** 1–2 vCPU, 2 ГБ RAM, 20–30 ГБ NVMe, Ubuntu 24.04, публичный IPv4. Нагрузка небольшая: один
  процесс Node и SQLite.
- **Домен.** Нужен для HTTPS (Telegram и ЮKassa шлют вебхуки только на HTTPS с настоящим сертификатом, Mini App
  не открывает http). `.ru` стоит порядка 200–500 ₽ в год (reg.ru, Timeweb, nic.ru). Заведите поддомен
  `api.<домен>` с A-записью на IP сервера. Если домен уже есть — используйте его.

## Шаг 2. Подготовка сервера (делается заранее, пользователи не затронуты)

Всё нужное лежит в [`server/deploy/`](../server/deploy): юнит systemd, конфиг Caddy, образец переменных,
скрипт обновления.

```bash
# от root, один раз
adduser --disabled-password --gecos "" deploy && usermod -aG sudo deploy      # свой пользователь с ключом SSH
useradd --system --home /var/lib/sedim --shell /usr/sbin/nologin sedim         # от него работает сервер
mkdir -p /var/lib/sedim /etc/sedim && chown sedim:sedim /var/lib/sedim
ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw enable              # наружу только SSH, 80, 443
# вход по паролю выключить (PasswordAuthentication no в /etc/ssh/sshd_config), root по SSH — тоже
apt-get install -y unattended-upgrades caddy                                    # автообновления безопасности + HTTPS-прокси

git clone https://github.com/paradox6499/meal-planner.git /opt/sedim && cd /opt/sedim/server && npm ci --omit=dev
cp deploy/sedim.service /etc/systemd/system/ && cp deploy/Caddyfile /etc/caddy/Caddyfile   # в Caddyfile — свой домен
cp deploy/sedim.env.example /etc/sedim/env && chmod 600 /etc/sedim/env && nano /etc/sedim/env
systemctl daemon-reload && systemctl enable --now sedim && systemctl reload caddy
curl https://api.<домен>/health        # должно быть {"ok":true}
```

В `/etc/sedim/env` — **те же значения, что сейчас в Render** (Environment): `TELEGRAM_BOT_TOKEN`,
`TELEGRAM_WEBHOOK_SECRET`, **`HASH_SECRET`** (обязательно тот же — иначе «надгробия» удалённых аккаунтов
перестанут совпадать), `ADMIN_TELEGRAM_ID`, `YOOKASSA_*`. Новых значений не придумывайте. Секреты не
присылайте в чат — копируйте из Render прямо в файл на сервере.

Если репозиторий станет приватным, на сервере нужен deploy key (GitHub → Settings → Deploy keys, только чтение).

## Шаг 3. Репетиция (пользователи всё ещё на Render)

Цель — убедиться, что сервер поднимается, HTTPS работает и ВкусВилл отвечает, **не трогая боевые данные и не
давая дублей напоминаний**. Поэтому на репетиции в `/etc/sedim/env` стоит **заглушка**: `TELEGRAM_BOT_TOKEN=TEST:X`
(любой текст), без `ADMIN_TELEGRAM_ID`, без `YOOKASSA_*`, база пустая. Таймеры при этом запустятся, но боевым
пользователям ничего не отправят.

1. `systemctl start sedim`, затем `curl https://api.<домен>/health` → `{"ok":true}` (проверяет и сертификат).
2. `node scripts/probe-vkusvill.js` на сервере → «каталог доступен».
3. Вебхуки пока не трогаем: Telegram и ЮKassa по-прежнему шлют на Render.
4. Остановить сервис (`systemctl stop sedim`), очистить заглушечную базу (`rm /var/lib/sedim/data.db*`).

## Шаг 4. Переключение (ночью, ~15 минут)

Порядок важен — так не теряются платежи и не двоятся напоминания.

1. Render → сервис → **Suspend** (напоминания и вебхуки на нём прекращаются). Перед этим `/backup` в боте —
   последний снимок (несколько минут между снимком и остановкой — единицы событий аналитики).
2. На новом сервере: в `/etc/sedim/env` вписать **боевые** значения (вместо заглушек), положить снимок:
   `scp sedim-….db deploy@<ip>:/tmp/`, затем
   `sudo -u sedim cp /tmp/sedim-….db /var/lib/sedim/data.db && sudo systemctl start sedim`. При старте база сама
   дойдёт до актуальной версии схемы (в логе `применена миграция …`, `journalctl -u sedim -n 30`). Убедиться в
   `/health`. Снимок после этого удалить (`shred -u /tmp/sedim-….db`) — это данные пользователей.
3. **Вебхук Telegram** — на новый адрес (команда из `server/README.md`, шаг 9):
   ```bash
   curl "https://api.telegram.org/bot<TOKEN>/setWebhook" -d "url=https://api.<домен>/telegram/webhook" -d "secret_token=<SECRET>"
   ```
4. **Вебхук ЮKassa** — личный кабинет → Интеграция → HTTP-уведомления: адрес
   `https://api.<домен>/yookassa/webhook`, события `payment.succeeded`, `payment.canceled`, `refund.succeeded`.
   Платежи, созданные за время простоя, догоняет сверка при старте сервера — вручную ничего делать не надо.
5. **Фронтенд**: GitHub → Settings → Secrets and variables → Actions → Variables → `VITE_BACKEND_URL` =
   `https://api.<домен>` (без слэша), затем перезапустить деплой Pages (Actions → Deploy → Run workflow).
6. Проверка по порядку: `/health`; в боте `/diag` (должно быть «отвечает»); открыть приложение, собрать план
   (настоящие цены, один запрос на списание слота); `/report`; в кабинете ЮKassa — доставка тестового
   уведомления прошла.

Откат (если что-то пошло не так в первые часы): Render → Resume, вернуть `setWebhook` и `VITE_BACKEND_URL`
на старый адрес. Всё, что произошло на новом сервере за это время, на Render не попадёт — поэтому откат только
в первые минуты и только если новый сервер совсем не поднялся.

Через неделю без проблем: удалить сервис и диск на Render (там ещё лежит копия базы с данными пользователей).

## Шаг 5. После переезда

- **Бэкапы.** Бот присылает файл базы в Telegram (чужой сервис, вне РФ): для 152-ФЗ лучше хранить копии в
  российском S3 (Selectel/Timeweb/Yandex Object Storage) + снимки диска у провайдера. Могу добавить выгрузку в
  S3 без новых зависимостей — скажите.
- **Мониторинг.** Алерты админу уже есть (каталог, платежи, ошибки). Добавьте внешний пинг `/health`
  (UptimeRobot или аналог) на случай, если упадёт сам сервер.
- **Обновления.** `bash /opt/sedim/server/deploy/deploy.sh` на сервере (код забирается из git, сервер
  перезапускается, скрипт проверяет `/health`). Автодеплоя нет — это сознательно: боевой сервер не должен
  меняться от случайного push.
- **Второй этап — фронтенд туда же.** Статику (папка `dist/`) можно отдавать тем же Caddy с того же сервера, с
  отдельным доменом. Плюсы: всё в РФ, не нужен GitHub Pages, а значит можно сделать репозиторий приватным. Цена:
  сменить адрес Mini App в BotFather и в `WEBAPP_URL`. Делать после стабильной работы шага 4.
- **Юридическое (не юридическая консультация — проверьте у юриста).** Обычно для оператора персональных данных
  нужно уведомление Роскомнадзора, а при передаче данных за границу (Telegram, если он считается таковой) — свои
  уведомления. Политика конфиденциальности должна называть, где хранятся данные: после переезда — «на серверах в
  РФ у <провайдер>».

## Если не поможет

Если пробы не проходят ни с одного российского адреса: ВкусВилл блокирует по другому признаку. Варианты —
написать им (у MCP-каталога есть контакт для интеграций) и попросить доступ для нашего адреса, либо временно
работать без цен (режим уже честный: план без цен, слот не списывается, сумма — оценка).
