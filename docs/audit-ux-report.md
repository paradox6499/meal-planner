# UX/продуктовый аудит «Съедим» — отчёт

Дата: 2026-09-28 · Коммит, на котором проводился аудит: `70aae84` (номера строк
ниже — по нему). Промпт аудита: `docs/audit-ux-prompt.md`.

## Как проверялось

- Приложение пройдено руками в браузере на ширине телефона (375 px), дев-сервер
  `npm run dev`.
- Вне Telegram `initData` нет, поэтому `window.Telegram.WebApp` подменялся
  заглушкой, а бэкенд — моком (временный `.env.local` с
  `VITE_BACKEND_URL`, подмена `window.fetch`; после аудита всё удалено).
- Каталог ВкусВилл (MCP) в сценарии новичка — **настоящий**.
- Состояния «Pro», «лимит исчерпан», «ВкусВилл недоступен», «локальный план
  потерян, есть история» — заданы моком.
- Серверная логика лимита (`server/src/app.js`) проверена **только по коду**,
  на живом сервере не запускалась.

Пометки в отчёте: **[проверено]** — воспроизведено в браузере; **[по коду]** —
выведено из чтения кода, не воспроизводилось.

Серьёзность: **критично** — теряются деньги/бесплатный план; **высокая** —
вероятная точка ухода; **средняя** — заметное трение; **низкая** — текст/косметика.

### 1.2 Вернувшийся пользователь, обычная неделя

**Тапов до «что сегодня готовить»:** 0 — приложение открывается сразу в план
(хорошо). Но дни подписаны «День 1…7», без дат/дней недели и без подсветки
«сегодня» — какой день сегодня, человек высчитывает сам. **Средняя.** [проверено]

**Тапов до «собрать новый план»:** задумано 4 (Заново → магазин → Далее →
Собрать список). По факту, из-за п. 1.1-6, профиля нет, и `reset()`
(`src/App.jsx:628-636`) обнуляет рацион/технику/аллергии — **снова 9 шагов и
12 тапов** с повторными ответами. **Высокая.** [проверено]

**Бесплатный план может сгореть сам. Критично.**
- [проверено] Эффект `src/App.jsx:464-466` вызывает `submitPlanToBackend`
  (`POST /api/plan`) на каждое монтирование с восстановленным из localStorage
  планом и на каждую замену блюда (`swapMeal` меняет `planView`). По логу
  запросов: 1 запрос при открытии (в dev — 2 из-за StrictMode) и +1 на каждую
  замену.
- [по коду] Сервер (`server/src/app.js:372-387`) на каждый принятый
  `/api/plan` пишет `plan_generated` и при `usedThisWeek >= FREE_PLANS_PER_WEEK`
  списывает покупной кредит (`consumeExtraPlanCredit`).
- Следствие: на второй неделе человек открывает приложение, видит прошлый
  план — и это открытие уже засчитано как новая бесплатная сборка. Жмёт
  «Заново», проходит визард — «лимит исчерпан», хотя ничего не собирал.
  С купленным за 59 ₽ кредитом то же: переоткрыл приложение — кредит ушёл на
  старый план.
- Формально баг, а не UX, но на воронку влияет сильнее всего остального.

**Путаница «смотреть план» vs «новый план»** — не на входе, а в одном месте:
кнопка «Заново» рядом с шестерёнкой, без подтверждения, молча уводит из плана
в визард. Из визарда назад к плану не вернуться: на первом шаге «Назад» скрыт,
`PlanSlotsBar` рендерится только при `done` (`src/App.jsx:1163`). Вернуться
можно только перезапуском приложения. Само слово «Заново» читается как
«сброс», а не «план на следующую неделю». **Высокая.** [проверено]

Для Pro: «Заново» (перезаписывает текущий слот) и «+ Ещё план» (новый слот)
стоят рядом — две разные «новые» кнопки. Чипы слотов подписаны только
названием магазина — два плана ВкусВилл неотличимы (комментарий у
`PlanSlotsBar`, `src/App.jsx:2302-2308`, обещает «магазин + бюджет», в коде
только магазин). **Средняя.** [проверено]

## 2. Дополнительно

### 2.1 FamilySection

- Блок в самом низу Аккаунта (Аккаунт ≈ 4 экрана), после всего профиля.
  Свободному пользователю не виден вообще (`src/App.jsx:1855`).
- Два шага: «Создать семью» → «Пригласить **ещё**» (хотя в семье пока только ты).
- **Текст приглашения обещает неправду**: «увидим один и тот же список
  покупок» (`src/App.jsx:1883`). На деле у каждого свой план со своими
  рецептами; общая только отметка «уже есть дома» — и только для продуктов,
  совпавших по названию.
- Приглашённый вступает молча при открытии (`src/App.jsx:228-232`), без
  подтверждения; попадает на «Шаг 1 из 9» и собирает собственный, другой план
  за свой бесплатный лимит. Что он в семье — ему не сообщается.
- Участник без имени отображается как «Участник 123456789».
- Рилс №9 в `docs/content-plan.md` («на втором телефоне позиция сама
  отмечена») обещает больше, чем есть: обновление — только при следующем
  открытии и только при совпадении продукта.

### 2.3 Пустые состояния и ошибки: сбой ВкусВилл

[проверено, при полном отказе MCP и `/api/prices`]

- Пользователь видит плашку «Не удалось получить цены… Сумма недостоверна» и
  огромное синее **«Итого за продукты: 0 ₽»**, а у каждого блюда стоит ~280 ₽.
  0 ₽ читается как «бесплатно» или «сломалось».
- Главное не сказано: рецепты тоже подменены на статический набор
  (`src/App.jsx:536-539`) — другие блюда, эмодзи вместо фото, ингредиенты со
  строчной буквы. Плашка винит только цены.
- «Заказать в ВкусВилл» остаётся активной (`canOrderForReal = storeId === "vv"`);
  без каталога сборка корзины, скорее всего, упадёт с сырым `err.message`
  («Не получилось собрать корзину: Failed to fetch») — [по коду], заказ не
  нажимался.

### 2.4 Контент-план vs реальное приложение

- Рилсы 01/02: «30 секунд», «быстрее, чем чай» — у новичка 12 тапов + ~19 с
  сборки. В самом ролике 02 противоречие: раскадровка «ускоренная (x3) запись
  экрана», подпись «без ускорения монтажом».
- Рилс 04 («цены настоящие, не усреднённые»): на экране плашка «цена не
  найдена для части товаров», в списке «Лавровый лист 1 шт · 60 ₽» рядом с
  «Соль 2 г · 0 ₽».
- Рилс 09: см. 2.1.
- Рилс 07 («помнит „уже есть дома“») — соответствует.

## 3. Топ-5 фиксов по влиянию на конверсию

1. **Перестать засчитывать повторные отправки плана как сборку.**
   `src/App.jsx:464-466`, сервер `server/src/app.js:372-387`. Отправлять
   засчитываемый `/api/plan` только из `handleFinish`; замены блюд и смену
   времени напоминаний — отдельным запросом, который не пишет
   `plan_generated` и не списывает кредит. Без этого фиксы 3–4 бессмысленны.
2. **Сохранять профиль автоматически в конце первого визарда** (`handleFinish`).
   Повторная сборка — 4 тапа вместо 12, ответы перестают обнуляться в `reset()`.
3. **Граница платы — один ясный экран:**
   - проверять лимит **до** визарда, по нажатию «Новый план»;
   - показывать дату: «Следующий бесплатный — 3 октября» (`createdAt` последнего плана + 7 дней);
   - «Назад» ведёт к своему плану, не в визард;
   - одна основная кнопка «Собрать сейчас — 59 ₽», под ней строка-ссылка
     «или Pro: 299 ₽ за 30 дней, без автосписания — безлимит, напоминания, семья»;
   - одинаковое название Pro-кнопки везде;
   - после оплаты бот пишет «Оплата прошла — открыть приложение» с web_app-кнопкой.
4. **Экран плана как «дом»:**
   - дни — датами/днями недели, «Сегодня» подсвечено, при открытии прокрутка к нему;
   - «Заново» → «Новый план»; для Pro — с подтверждением, что текущий слот перезапишется;
   - закреплённая внизу кнопка «Заказать»;
   - название блюда отдельной строкой, время и цена — второй строкой.
5. **Короче первый визит (9 → 5 шагов):**
   - строка ценности на первом шаге («Меню на 7 дней + список покупок с ценами ВкусВилл»);
   - ВкусВилл выбран по умолчанию, остальные свёрнуты в «Другие сети — скоро»;
   - ответы по умолчанию: «Как обычно», «Готовлю на всём»;
   - «Кухню» и «Время готовки» — в Аккаунт.

Вне топ-5, но дёшево: исправить текст приглашения в семью (`src/App.jsx:1883`);
при сбое ВкусВилл — честная плашка «показали базовый набор рецептов с примерными
ценами», итог «≈ N ₽» вместо 0 ₽, кнопка заказа отключена; кнопка «Продлить» для
действующего Pro; убрать «Отменить можно в любой момент» с лендинга.

## 4. Единый домашний экран — рекомендация

**Всегда показывать — нет.** Самый частый сценарий (открыть и посмотреть блюдо
на сегодня) сейчас стоит 0 тапов; обязательный домашний экран добавит +1 тап к
каждому открытию. Путаница, которую он должен снять, возникает не на входе, а в
двух местах — безвозвратное «Заново» и экран лимита без пути назад. Их закрывают
фиксы 3 и 4.

**Показывать экран выбора только при неоднозначности:**
- план старше 7 дней: «План прошлой недели · Собрать новый / Открыть прошлый»;
- локальный план потерян, но есть в истории (то, что сейчас делает LastPlanGateView);
- первое открытие после оплаты.

Во всех остальных случаях — сразу план.

## 5. Что не стоит трогать сейчас

- Реальный заказ только во ВкусВилл, остальные сети «скоро» — нормально, если
  не подавать их как равноценный выбор.
- Семья без синхронизации в реальном времени (обновление при открытии) —
  достаточно честно это написать.
- Скользящее 7-дневное окно вместо календарной недели — не переделывать, только
  показывать дату.
- Email для чека при оплате — требование 54-ФЗ, уже запоминается локально.
- «Диагностика подключения» в Аккаунте — полезна поддержке на этой стадии,
  можно свернуть глубже, но не убирать.
- История без списка покупок, «бэкенд опционален» (без него лимита нет),
  реферал на 7 дней — сознательные упрощения ранней стадии.
- Сбор пола/возраста/веса — сознательно отклонён, не предлагается.
