# meal-planner

Telegram Mini App — бот [@s_edim_bot](https://t.me/s_edim_bot): план питания
на неделю под бюджет и список покупок с реальными ценами ВкусВилл.
Визард для новичка — 6 шагов (магазин → семья → приёмы пищи → бюджет →
рацион → аллергии; кухня, техника и время готовки — в Аккаунте), у
вернувшегося — 2 (магазин и бюджет, ответы запоминаются). Есть бесплатный
лимит (1 план в неделю), разовая покупка «ещё один план», подписка Pro
(напоминания от бота, несколько планов, общий список на семью),
реферальная программа. Бэкенд — `server/` (Node.js, SQLite, ноль
runtime-зависимостей), фронтенд — React + Vite на GitHub Pages.

## Разработка

```bash
npm install
npm run dev
```

Требует Node.js — на машине, где изначально собирался проект, его не было,
поэтому есть [preview/index.html](preview/index.html) — рабочий просмотрщик
без сборки (Babel прямо в браузере, React/иконки с CDN). Для реальной
разработки с HMR используйте `npm run dev` там, где Node есть.

## Структура

- `src/App.jsx` — визард, экран плана, Аккаунт и все модальные окна.
- `src/lib/` — логика без интерфейса: сборка плана (`planLogic.js`),
  вызовы бэкенда с таймаутами (`backend.js`), рецепты ВкусВилл, локальное
  хранение (профиль, планы, согласие) — у каждого файла рядом `*.test.js`.
- `server/` — бэкенд, отдельный пакет, см. [server/README.md](server/README.md)
  (там же ранбуки: возврат, бэкап, удаление данных пользователя).
- `public/privacy.html`, `public/terms.html` — политика конфиденциальности и
  пользовательское соглашение (раздаются рядом с приложением).
- `src/data/recipes.js` — рецепты, отделы магазина, аллергены. Контент, не
  логика — обновляется правкой этого файла.
- `src/data/prices.json` — мост к реальным ценам из
  [grocery-budget](https://github.com/paradox6499/grocery-budget) (соседний
  проект). Пустой `{}`, пока живые цены не подключены — тогда бюджет
  считается по оценочным `cost` из рецептов, с честной пометкой в интерфейсе.
- `docs/telegram-bot-architecture.md` — исходный план архитектуры бота
  (напоминания, семья, Аккаунт). Всё из него уже реализовано, актуальное
  состояние — в `server/README.md`.
- `docs/audit-*.md` — отчёты технического и UX-аудитов и промпты для них,
  `docs/audit-followup-*.md` — что сделано по аудитам и что осталось.

## Деплой

GitHub Actions ([`.github/workflows/deploy.yml`](.github/workflows/deploy.yml))
собирает проект и публикует на GitHub Pages при каждом пуше в `main`.
Требуется один раз включить в репозитории: **Settings → Pages → Build and
deployment → Source → GitHub Actions**.
